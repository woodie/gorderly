# gorderly v0.4.1

## Fix

`v0.4.0`'s pickup of `github.com/woodie/spec` v0.2.0 via a `go.mod`
`replace` directive broke `go install github.com/woodie/gorderly@latest`
outright: `go install pkg@version` treats the target module as the main
module, and Go unconditionally rejects any `replace` directive under
that treatment -- true even though `spec` is only ever imported by
`gorderly`'s own `_test.go` files, never by the shipped binary.

Reverted `gorderly`'s test suite to plain upstream `sclevine/spec`
v1.4.0, no `replace`: `it.BeforeEach` calls (the only fork-specific hook
actually used here -- `AfterEach`/`JustBeforeEach` never were) are back
to `it.Before`. No behavior change to `Parse`/`Render`/`gorderly`'s
actual output -- test-suite tooling only. See `docs/FRAMEWORK.md`'s new
"Exception: `go install`-able CLI tools" note for the general lesson.

## Notes

If you installed `v0.4.0` via `go install github.com/woodie/gorderly@latest`
and hit "must not contain directives that would cause it to be
interpreted differently than if it were the main module", that's this
bug -- `go install github.com/woodie/gorderly@latest` now resolves to
this release and works normally.
